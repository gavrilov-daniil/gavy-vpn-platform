# Roadmap

Все 4 контура строятся **вширь**: базовый рабочий функционал каждого, затем углубление.
Контуры: **A** Инфра-ядро · **B** Пользователи и деньги · **C** Поддержка · **D** CRM/воронка.

Принятые решения (не пересматриваем без причины):
- Ядро сети воспроизводим 1:1 (VARIANTS, loopback-failover, geo-free split) — иначе мигрированные клиенты отвалятся.
- Мерчанты — **в БД и управляются админкой**, не в env. Несколько аккаунтов одного провайдера, test/live, включение без рестарта.
- **Два бота**: клиентский (продажи/самообслуживание/поддержка) и админский (алерты операторам).
- `org_id` — колонка везде, RLS-машинерии нет до первого реального второго тенанта.
- Go — только в node-agent (статический бинарь без Docker). Всё остальное TypeScript.

## Сделано

### Фундамент
- Монорепо pnpm+turbo: `apps/{core,bot,admin,node-agent}`, `packages/{db,xray-config,core-kit,payments}`.
- Схема БД — **61 таблица**, все контуры + partial unique индексы и триггер атрибуции
  (идемпотентность на уровне БД, а не блокировок).
- `@vpn/core-kit`: HTTP с ретраями/бэкоффом/джиттером и аудитом, маскирование секретов,
  идемпотентность (`tryClaim`, `buildIdempotencyKey`), AES-256-GCM для кредов. **12 тестов.**

### Контур A — инфра-ядро
- `@vpn/xray-config`: генератор **клиентских** конфигов (VARIANTS + loopback-failover +
  geo-free split + observatory) с инвариант-валидатором, и генератор конфигов **нод**
  по ролям (exit/relay/front) с каскадами. Детерминированный `config_hash`. **16 тестов.**
- Выдача подписки: `/auto/:shortUuid` и legacy `/api/sub/:id`, заголовки байт-в-байт, UA-гейт.
- API для node-agent (dial-out pull): desired-state, heartbeat, идемпотентный приём статистики.
- Каскады: скрещивание relay↔exit, статус — непрерывная функция от reported-state обеих нод
  (канал уходит из подписки, если плечо разъехалось).
- node-agent (Go): reconcile-loop, brownfield-импорт Reality-ключей, durable-буфер статистики.

### Контур B — деньги
- 5 мерчантов: `stars`, `cryptobot`, `oxapay`, `paritypay`, `pal24`. Алгоритмы подписей
  перенесены буквально из прода и покрыты тестами. **18 тестов.**
- Управление мерчантами из админки: подключение, ключи (шифруются), test/live, приоритет,
  health-check. Наружу креды не отдаются.
- Единый платёжный flow вместо 5 copy-paste сервисов. Ledger-first: баланс = SUM, append-only.
- **Проверено вживую**: поддельная подпись → 401; валидная → подписка +30 дней и ledger ±500 ₽;
  8 повторных доставок (3 последовательных + 5 параллельных) не задвоили ни дни, ни деньги.

## В работе

- **Контур C** — поддержка: тикеты (`conversation`/`message`), приём из бота, ответ оператора,
  дедуп входящих по `telegram_update_id`.
- **Контур D** — CRM: события воронки, attribution через deep-link `start=c_<CODE>` (first-touch),
  сегменты, рассылки с троттлингом и дедупом, триггерные касания (дожим продаж).
- **Боты** — клиентский (grammy, webhook, способы оплаты берутся из БД, Stars через
  `replyWithInvoice`) и админский (алерты).

## Дальше

### Ближайшее
- Подключение всех модулей в `core`, сквозная проверка: бот → счёт → вебхук → подписка → выдача.
- Админка: экраны мерчантов, нод, подписчиков, платежей, поддержки, рассылок.
- Воркеры и расписание: истечение подписок, напоминания о продлении, реф-награды,
  safety-net по `desired_hash != last_acked_hash` (закрывает разрыв commit→enqueue).
- Анти-абьюз: детект аномалий по статистике (объём, up/down→1, ip_fanout) → throttle/suspend.

### Гейт перед переключением боевого трафика
Два спайка (нужен доступ к боевой панели):
1. **Golden byte-diff**: новый генератор собирает базу, семантически совпадающую с текущим
   Remnawave `/api/sub/<id>/json` для реального юзера. Любой diff — блокер.
2. **Takeover ноды без смены `pbk`**: node-agent забирает существующую exit-ноду с импортом
   ключа; уже розданные конфиги продолжают коннектиться.

### Требует решения заказчика
- **Где хостится core.** Beget 1CPU/1GB не потянет новый стек + работающий Remnawave.
  Нужен отдельный бокс, желательно вне РФ-хостинга («Антифрод 2.0»; там же лежит ключ
  подписи конфигов — единая точка компрометации).

## Топ-риски

| Риск | Закрытие |
|---|---|
| Перегенерация Reality-ключей рвёт клиентов | brownfield-импорт keypair, спайк 2 |
| Смена URL подписки — отвал клиентов | тот же host/path/заголовки (`migration.md`) |
| Дрейф генератора → молчаливо сломанный failover | инвариант-валидатор + golden byte-diff |
| Две панели дерутся за ноду | cutover нода-за-нодой, host в Remnawave гасится |
| Утечка payload (plain-text pbk + uuid) | UA-гейт, rate-limit, неугадываемый short_uuid, дешёвый revoke |
| core на РФ-хостинге изымут | вынести core вне РФ (решение заказчика) |
| Двойная активация платежа | `UNIQUE(provider, provider_payment_id)` + `UNIQUE(payment_id)` на активации |
| Оплата пришла, ноды не узнали | safety-net cron по `desired_hash != last_acked_hash` |
| Блокировка мерчант-аккаунта | несколько мерчантов одного провайдера + переключение без рестарта |
